### Design Rulings

#### Ruling A: Profile Auth Schema Invariant

When Item 2 extends `RuntimeProfile`:
- **MAY:** Add `Provider` field (credential mechanism selection).
- **MUST NOT:** Add `Scope` or `AllowedHosts`.

**Rationale:** Gate is always constructed from tool definition (`def.Auth.Scope` and `def.Auth.AllowedHosts`). Profile substitutes credential acquisition mechanism only, never the token audience or host restrictions.

**Current state:** No top-level `Auth` field on `RuntimeProfile` today — rule enforced structurally.

#### Ruling B: `*IndeterminateRecord` as Non-Fabricated-Output Representation

**Problem:** `StepResult.Output == nil` is ambiguous (tool returning empty outputs also yields nil).

**Solution:** Embed `*IndeterminateRecord` on `StepResult`.
- Non-nil pointer = completion unknown.
- `Output` remains nil (not fabricated).
- Fields: `RunID`, `StepID`, `ToolName`, `ActionName`, `Classification`, `EndpointHost`, `AttemptNumber`, `Deadline`, `FailureTime`, `TransportErrCategory`.

**Design rationale:** Nil `Output` + nil `IndeterminateRecord` = tool returned empty output (valid). Nil `Output` + non-nil `IndeterminateRecord` = completion unknown (trace-safe evidence, no fabrication).
