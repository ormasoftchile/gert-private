## Key findings — Three-Tier Preflight

- **Tier 1 (local, opt-in):** Check tools exist on PATH; check IMDS metadata endpoint reachable.
- **Tier 2 (live, opt-in):** Acquire credentials; probe endpoints. Only when explicitly requested.

## Key findings — Error Taxonomy

Existing `binding/tool-not-found` code is too coarse. Must split into 5 codes with distinct operator remediations:
- `config/tool-unresolved` — authoring error
- `config/no-binding-for-profile` — environment not configured
- `config/binding-incomplete` — static config incomplete
- `auth/credential-failure` — runtime auth issue, not configuration
- `transport/endpoint-unreachable` — runtime network issue, not configuration

## Critical blockers

1. **Host protocol missing:** protocol_version, capability advertisement (required for Tier 0), run_id/step_id audit fields, CancelRequest message type.
2. **Idempotency contradiction:** Can't declare idempotent without schema change, but §13 forbids schema changes.
3. **Late-result discard wrong for destructive actions:** Must distinguish read-only (discard OK) vs. mutating/destructive (halt-indeterminate required).
4. **Phase-ordering risk:** Reconnect deferred to Phase 3, but HTTP timeouts arrive in Phase 1. Mitigation: ship Phase 1 with explicit "halt-on-timeout" policy. Alternative: restrict Phase 1 to read-only tools only.
