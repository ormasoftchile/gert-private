## Technical Findings

- **Critical discovery:** Approval gate coverage gap — direct-invocation path has zero enforcement
- **Field collision:** `allowed-environments: ["real"]` is RunMode axis, not deployment-context axis
- **Scope impact:** Interactive-unspecified default would break existing runbooks without migration path
- **Feasibility:** All SQL team requirements are implementable; main cost is clarification, not invention

## Design Outcomes

- AllowedModes field added to ToolGovernance (RunMode dimension)
- Profile `attendance` decoupled from TTYOutput (which conflates three properties)
- Test-context binding check at plan time (0.5 days)
- Grandfathering rule enables day-1 safety without day-1 breakage

## Notes

Source-grounded verification discovered that the dangerous behaviors (unspecified defaulting to read-only, direct-invocation bypass) were not caught by the initial SQL team request review. Early verification prevented shipping with invisible safety debt. The grandfathering recommendation preserves both the new safety principle (unspecified fires gate) and backwards compatibility (explicit prior opt-outs honored).
