## Context

When tasked with researching technology landscapes to inform design decisions, a systematic approach yields comprehensive, actionable insights. This skill documents the research methodology used for the gert v2 design research.

## Patterns

### Research Structure

Break research into clear domains:
1. **Landscape Survey** — Definitions, evolution, current tools
2. **Pattern Analysis** — Common patterns across systems
3. **Governance & Compliance** — Standards, regulations, frameworks
4. **Implementation Patterns** — How systems implement key features
5. **Schema/DSL Design** — Language and interface patterns
6. **Synthesis** — What works, what doesn't, recommendations

### Source Diversity

Combine multiple source types:
- **Academic papers** — Foundational concepts, validated approaches
- **Industry tools** — Real-world implementations, battle-tested patterns
- **Standards** — W3C, CNCF, ISO, ITIL, compliance frameworks
- **Open source projects** — Code-level pattern examination

### Web Research Strategy

For each domain:
1. Start with broad definitional queries
2. Follow with specific tool/framework comparisons
3. Search for academic research and papers
4. Investigate standards and specifications
5. Look for comparative analyses

### Synthesis Framework

For each researched area, document:
- **What it is** — Clear definitions
- **Why it matters** — Use cases, benefits
- **How it works** — Patterns, mechanisms
- **Who uses it** — Industry adoption
- **Trade-offs** — What works, what doesn't
- **Recommendations** — Specific guidance for the design

### Grounding Recommendations

Every recommendation should be:
1. **Evidence-based** — Cite specific systems or research
2. **Contextualized** — How it applies to this project
3. **Prioritized** — High/medium/low impact and effort
4. **Actionable** — Specific enough to implement

### Gap Analysis

Explicitly identify:
- **What v1 gets right** — Preserve and build on strengths
- **What industry has learned** — Patterns not yet in v1
- **Open questions** — Unresolved issues in the field

## Deliverable Structure

A comprehensive research brief should include:
1. **Executive Summary** — Key findings, top recommendations
2. **Domain Sections** — One per research area
3. **Pattern Catalogs** — Tables, examples, code snippets
4. **Recommendations** — Specific, prioritized, actionable
5. **References** — Academic, industry, standards
6. **Conclusion** — Next steps, review cycle
