## Dispatch

Killua was tasked to resolve the WebSocket disconnect loop that prevented the web application from receiving server events.

## Work

1. Root cause analysis:
   - Identified that Playwright's click() method triggered tab button twice
   - First click → load tab → create view → WebSocket connects
   - Second click (immediate) → load same tab → dispose old view → create new view → old WebSocket closes

2. Primary fix in web/src/main.ts:
   - Added `currentTab` guard to prevent reloading the same tab
   - Prevents redundant view recreation and disconnect loops
   - Tracks current tab state across navigation events

3. Supporting fixes:
   - web/vite.config.ts: Changed WebSocket proxy target from `ws://` to `http://` (correct format)
   - web/playwright.config.ts: Added `VITE_HMR=false` to disable HMR during tests (defensive)
   - ext/serve/pkg/serve/serve_http.go: Added ping/pong handlers (defensive)

## Changes

**Commit:** f309294

- Fixed Vite proxy WebSocket target format
- Added defensive HMR and ping/pong configuration

## Result

✅ WebSocket now stays connected  
✅ No more disconnect loop  
✅ Server can send events to browser  
✅ Web application fully functional

## Lessons Learned

1. Playwright can trigger multiple clicks - always guard against re-entrancy in UI event handlers
2. WebSocket proxy target in Vite should be `http://`, not `ws://` (upgrade happens at HTTP level)
3. Add currentTab/currentState tracking to prevent unnecessary view recreation
