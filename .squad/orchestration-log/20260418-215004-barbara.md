### Interactive Step Type Contracts (§14.6)

Enhanced §14 Input Provider Framework to define how providers serve choice/decision/collector step types.

#### 1. Choice Step Contract (§14.6.1)

- **JSON-RPC method:** `provider/choice`
- **Request fields:** stepId, prompt, options array (value + label pairs), optional default
- **Response:** selected value (must match option value exactly)
- **Built-in provider:** `prompt` (terminal numbered list)
- **Validation:** Ensures selected value matches an option

#### 2. Decision Step Contract (§14.6.2)

- **JSON-RPC method:** `provider/decision`
- **Request fields:** stepId, prompt, routes array (route + label pairs)
- **Response:** selected route label
- **Design principle:** Provider does NOT need graph knowledge
- **Responsibility:** Engine resolves route label to target node and validates existence
- **Flow control:** Decision result NOT stored as variable (pure control flow)

#### 3. Collector Step Contract (§14.6.3)

- **JSON-RPC method:** `provider/collect`
- **Request fields:** stepId, instructions, fields array with type-specific constraints
- **Field types:** text, multiline, file, url, number, date
- **File upload support:**
  - MIME type restrictions (images, documents, archives, logs)
  - Size limits per field
  - SHA-256 verification
- **Response:** values map + artifacts array with storage metadata
- **Artifact metadata:** field, filename, contentType, sizeBytes, sha256, storagePath
- **Built-in storage:** `.gert/runs/<runId>/artifacts/`

#### 4. Provider Capability Matrix (§14.6.4)

- **Table format:** Shows which built-in providers support which step types
- **Capability coverage:**
  - `prompt` supports all three (choice, decision, collector)
  - `env`, `file`, `workspace` support only input resolution (not interactive steps)
- **External provider integration:**
  - Providers advertise capabilities in `provider/initialize` handshake
  - Capabilities object: `{supportsChoice: bool, supportsDecision: bool, supportsCollector: bool}`
  - Fallback behavior: If provider doesn't support step type, engine uses built-in `prompt`

### Design Decisions

| Decision | Rationale |
|----------|-----------|
| Capability advertisement via handshake | Enables graceful fallback without duplicating provider discovery logic |
| Decision does NOT store route as variable | Pure control flow; if value needed, author adds explicit assignment in target |
| Provider doesn't know runbook graph | Clean separation of concerns; provider returns route label only |
| File size limits enforced by provider | Prevents partial uploads; provider rejects before storage |
| SHA-256 in artifact metadata | Enables integrity verification and evidence chain validation |
| External providers MAY use remote storage | Supports cloud deployments (S3, Azure Blob) with signed URLs |
