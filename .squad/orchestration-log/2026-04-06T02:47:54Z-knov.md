## Output

**Decision document:** `.squad/decisions/inbox/knov-playwright-strategy.md`

**Key design principles:**
- Agent-first test output (structured JSON results)
- Fast fixture strategy (sub-5-second startup via persistent Go server)
- Flakiness mitigation (explicit waits, streaming indicators, graph-ready signals)
- Page Object Model for maintainability
- data-testid discipline for stable selectors

**Test scenarios (15 total):**
- **Runner (R1-R10):** Linear execution, tool invocation, branching, iterates, graph rendering, error handling
- **Editor (E1-E3):** YAML round-trip fidelity, real-time sync, metadata editing
- **Catalog (C1-C2):** Tool discovery, detail drill-down

**Autonomous dev loop:**
```
Agent makes code change → npm run test:e2e --grep "..." → read agent-report.json → interpret PASS/FAIL
```

**Agent-friendly output format:** Structured JSON with:
- Summary (total, passed, failed, duration)
- Per-test assertions (check, result, expected, actual)
- Screenshots on failure
- Simple "PASS" or "FAIL" verdict for agent decision

**Flakiness mitigation strategies:**
- Explicit state waiters (poll for data-state attribute)
- Output-complete signal before reading stdout
- Graph-ready indicator (data-graph-ready, data-node-count, data-edge-count)
- Network idle detection
- Deterministic test data

**CI integration:** GitHub Actions workflow
- Runs after go-build-test succeeds (parallel to vscode-build-test)
- Headless Chrome, artifact capture on failure
- Auto-retry on network errors

**4-week implementation roadmap:**
- Week 1: Foundation (directory structure, fixtures, BasePage)
- Week 2: Runner tests (R1-R5)
- Week 3: Editor & Catalog tests (E1-E3, C1-C2)
- Week 4: CI integration & hardening
