**Focus:** Fixing input form collection flow in runbook execution

## What Was Broken

The runbook input collection form was not appearing before execution started:
- User inputs defined in runbooks were not being collected
- Execution proceeded immediately with empty variables
- Root cause was a schema/code mismatch in the input filter

## What Was Found

**Audit by Gon:**
- Code was filtering inputs by `from === 'user'`
- Schema defines inputs with `from: prompt`
- All example runbooks use `from: prompt` correctly
- The filter never matched any inputs

**Verification by Knov:**
- Confirmed visually that no input form appeared
- Execution started immediately without collecting data
- Variables remained empty throughout execution

## What Was Fixed

**File:** web/src/views/runbookRunner.ts

1. **Fixed input filter on line 1301**
   - Changed: `from === 'user'` → `from === 'prompt'`
   - Reason: Align code with schema definition and example usage

2. **Added clarifying comment to InputDef**
   - Documents that inputs use `from: 'prompt'` source
   - Prevents future mismatches between schema and implementation
