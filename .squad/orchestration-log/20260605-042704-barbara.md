## New Error Codes (PLAN-001..009)

Nine new gate-level error codes introduced, all normalized as `PLAN-*`:

| Code | Raised By | Condition | Remediation | Category |
|------|-----------|-----------|-------------|----------|
| PLAN-001 | Parser/Planner | Unparseable expression wrapper (includes sub-error from grammar layer) | Fix flagged expression field | Aggregation |
| PLAN-002 | Planner | Undefined capture variable reference in expression — var not produced by statically reachable predecessor | Ensure variable captured before use | Semantic |
| PLAN-003 | Planner | `capture.default:` declared on subtree capture (plan-level alias for GCP-DEFAULT-SUBTREE) | Use `when: var != null` guard instead | Semantic |
| PLAN-004 | Parser | Forbidden Go-template syntax `{{ }}` detected in GIS field | Replace with `${...}` interpolation syntax | Migration-era |
| PLAN-005 | Parser | Forbidden infix operator (`&&`, `||`, `!`, infix `contains`) in GXL field | Replace with `and`, `or`, `not`, `str.contains()` function | Migration-era |
| PLAN-006 | Parser | Forbidden pipe expression in GCP capture path (`\| length`, etc.) | Replace with `len()` function in GXL after scalar capture | Migration-era |
| PLAN-007 | Planner | Grammar version mismatch — plan validated against incompatible grammar version | Re-validate runbook against current grammar | Compatibility |
| PLAN-008 | Planner | Keyword used as capture variable name (e.g., `capture: and: ...`) | Rename capture variable to non-keyword | Semantic |
| PLAN-009 | Planner | Cross-step capture path `step.X.*` where step X not statically reachable from declaring step | Re-order steps or add `when:` guard for conditional execution | Reachability |

### Design Rationale

- **PLAN-001..003 (Aggregation codes):** Allow runtimes to emit consistent top-level PLAN-* code for validation failure while preserving specific grammar code in `sub_error` field.
- **PLAN-004..006 (Migration-era codes):** Catch runbooks not processed by Stream E migration tooling. MUST be detected at parse time (not lazily).
- **PLAN-007 (Grammar version mismatch):** Protects replay determinism by ensuring mixed-version execution is impossible. Mechanism by which `ValidatedPlan.grammar_versions` field enforces compatibility.
- **PLAN-008 (Keyword capture var):** Extends GXL-PARSE-010 to planner level. Capture variable names are not GXL expressions but are referenced by GXL expressions.
- **PLAN-009 (Cross-step reachability):** Primary output of statically-reachable-step algorithm. Enables `GCP-PARSE-006` enforcement.

## Phase 2 Governance Gaps (Open Issues — OPQ-GATE-*)

### 🔴 OPQ-GATE-01 — In-flight grammar version upgrade (BLOCKING)

**Question:** What happens to a run mid-execution (e.g., suspended at approval gate) when runtime upgrades its grammar version?

**Option A (Strict):** Suspend run at next `NextAsync()` call, raise PLAN-007, mark run as VersionMismatch. Operator must re-validate, replay, or cancel.

**Option B (Sticky):** Run retains the grammar version it was validated against for its lifetime. Grammar upgrades only affect new runs. Runtime maintains version registry.

**Trade-off:**
- A: Safer (no mixed-version execution), but disruptive for long-running approval flows
- B: Friendlier for long-running flows, but requires version registry infrastructure

**Blocking Impact:** Gates OPQ-GATE-05 (plan-storage spec). Determines whether ValidatedPlan must include version snapshot or just reference current.

**Request:** Germán, please decide before Phase 2 begins.
