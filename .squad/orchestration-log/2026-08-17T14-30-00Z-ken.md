## Implementation Summary

### Chokepoint Selection

**Seam:** Engine pre-flight in `executeStep()` (`internal/engine/engine.go`), before executor dispatch.

**Rationale:** Single enforcement point for all transports regardless of underlying mechanism. Pre-existing plumbing was fully implemented but guarded by `if h.engine.cfg.GovernanceEvaluator != nil` — always true. No data threading needed; engine has access to both plan and approval gate.

### Policy Composition Architecture

Two-level governance (runbook + per-tool) composed at evaluation time:

1. **Runbook-level:** `plan.GovernanceSource` stored on `ExecutionPlan`. At `Start()/Resume()`, built into per-run `PolicyEvaluator` with `requireApproval` extracted from runbook governance block.

2. **Per-tool level:** In `executeStep`, tool def looked up from `plan.Tools`. If `toolDef.Governance.RequiresApproval != nil && *toolDef.Governance.RequiresApproval`, set `stepInfo.ToolRequiresApproval = true`.

3. **Composition:** Evaluator sets `result.RequiresApproval = e.requireApproval || step.ToolRequiresApproval` — monotone OR, binding guarantee preserved.

**Binding guarantee:** `require_approval: false` at runbook level cannot suppress `requires-approval: true` at tool level. Verified by `TestApproval_RunbookFalseCannotSuppressToolTrue`.
